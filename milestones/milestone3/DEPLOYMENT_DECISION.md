| Component          | Shape                | 2 things that drove this shape                                                                                                                                                                                                      | A shape I rejected and why                                                                                                                                                              | What would get us to switch                                                                                                                                                                                                                               |
|--------------------|----------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| FastAPI / API host | Long-running server  | It will be hit constantly so it should have very little overhead; It could be optimized over time with JIT                                                                                                                          | It could never be function-based, because it would be too complex to get FastAPI working in this way                                                                                    | For an API host, the only thing that could make this better is if was somehow integrated directly into the server, and if that made it significantly faster.                                                                                              |
| Gateway            | Long-running server  | It will be hit constantly so it should have very little overhead; Persistence makes configuration files work                                                                                                                        | It could never be function-based, because apache does not work in this way                                                                                                              | Similar to above, the only thing that would make us switch is if was directly integrated in a way that sped up the app significantly.                                                                                                                     |
| Image worker       | functional           | It is called less often; It is specialized for a task                                                                                                                                                                               | I decided a persistent container wouldnt be best because it would take extra compute during times with little traffic. The extra overhead would still cost less than this idle compute. | If we switched to batch jobs a container on demand would be better. If the hoster had a built-in ffmpeg we could use                                                                                                                                      |
| Matching worker    | Container on demand  | Jit compilation (with PyPy or experimental JIT) can make a big difference for string matching like this We could stream in the text data to require less memory                                                                     | I thought functional would be bad for this because we have to pass quite a bit of data at once, or a database connection. Both of these would make this "worse" in some way.            | If we had a more specialized way of searching, like offloading to the database using special select functions.                                                                                                                                            |
| Message broker     | Persistent container | The message broker needs to always be on, ready to handle a request. The setup time for erlang (behind RabbitMQ) is very long and would cause massive delays.                                                                       | Any container that needs to be restarted frequently is not appropriate for a tool with this size of startup time.                                                                       | Hosters often has their own message broker tools that might save us money to use.                                                                                                                                                                         |
| Notifer            | Container on demand  | These would go best in batch jobs (because of external APIs and long delays like this), and container on demand is almost built for this. A persistent container would be active when batches dont need to be done, taking idle cpu | There is almost no way to hook functional code to external tools like that would require.                                                                                               | If we switched to a communication tool that has a very simple, reliable API we could offload this work to just about anywhere. It is so simple to just publish to an API with a string token and string message, no extra complexity is needed sometimes. |
| Logger             | Persistent container | The persistent storage is needed for logs files. The data stream will virtually never stop with so many places writing logs                                                                                                         | This will be called so often that no extra overhead can be afforded                                                                                                                     | If a hoster hand sufficiently featureful automatic logging, we wouldnt need our own tool.                                                                                                                                                                 |
| Database | persistent container | Database requires persistence by definition; It should still be its own seperate place/container | Any other shape does not have the persistence it needs | I would be very willing to switch to a hoster-provided database, and that is very common.  In our case, it will likely cost more though |
